Meta Measure

April 5, 2026

Meta Measure takes a list of research ideas and plots them on a scatter graph—quantitative to qualitative on one axis, traditional to novel on the other—so you can see at a glance how a set of topics balances against each other methodologically. There's no scoring rubric baked into the app itself; every placement comes from Claude reasoning about each idea fresh, which makes the graph less a fixed taxonomy and more a snapshot of one model's judgment at one point in time.

The interesting part isn't the graph rendering, it's the prompt behind it. The API route sends the full list of ideas in a single request and asks for strict JSON back—coordinates for each idea plus a written explanation of the reasoning—and it explicitly asks the model to interrogate its own placements: what assumptions it made, what it favored by default, and whether its evaluation systematically privileges certain research approaches over others.

const message = `Given the following words: ${JSON.stringify(ideas)}

Your response must ONLY contain valid JSON in the following format, with no additional text:
{
  "ideas": [
    { "title": "string", "x": number, "y": number }
  ],
  "explanation": "string"
}

Evaluate each word on these scales:
- X-axis: Quantitative (-1) to Qualitative (1)
- Y-axis: Traditional (-1) to Novel (1)

In the explanation field, provide a detailed analysis of your reasoning process for
each placement... Be transparent about any default interpretations you applied when
information was limited. Address whether certain fields or methodologies were
implicitly favored in your evaluation and why.`;

That self-critique is asked for on every call, not bolted on as a separate step—the model has to justify its own coordinate system in the same response that produces it. The route itself is a thin Next.js handler behind a cookie-gated access check, with a regex fallback to pull a JSON object out of the response if Claude wraps it in extra text.
