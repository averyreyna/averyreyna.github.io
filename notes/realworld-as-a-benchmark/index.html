RealWorld as a Benchmark

RealWorld is a standardized demo app called "Conduit" (a Medium-like blogging platform), implemented in over 100 different tech stacks. Since every implementation builds the same app to the same spec, you can make apples-to-apples comparisons across frameworks and languages. It was inspired by TodoMVC, which did something similar for frontend frameworks only.

Why It Works as a Benchmark

  • A fixed API spec (primarily JSON declarations describing the expected shape of responses) means any backend, regardless of language, must satisfy the same contract; an automated Postman test suite verifies compliance objectively
  • It is realistic but tractable: articles, comments, tags, favorites, profiles, authentication, following, with enough moving parts to be interesting and small enough to actually build and analyze

What It Revealed in the Paper

  • The spec is deliberately a bit messy. It conflates concerns cleaner design would separate (unfollowing a user returns their full profile including bio; fetching articles bundles author profile, follower status, and favorite counts in one response). The authors treated this as a feature: if their approach could handle this awkward API, it would handle a cleaner one easily.
  • Existing implementations routinely violated the conventional three-layer architecture (routing → controller → model): controllers reaching into other controllers' models, routers calling the wrong controllers, "favorites" scattered across user and article code, concrete evidence for the illegibility problem the paper argues against.

Notes

The punchline: the concepts-and-synchronizations approach handled the full spec, passed the Postman suite, and respected clean module boundaries, which the surveyed conventional implementations largely failed to do. The benchmark gave the authors a credible, externally defined target rather than a self-serving toy example. See state in concept design for the formal machinery underneath.
