Elm: Introduction and Core Language

Elm is a functional programming language that compiles to JavaScript. In practice it promises no runtime errors, friendly error messages, reliable refactoring, and automatically enforced semantic versioning for all Elm packages; the compiler is doing real verification work, not just translation.

Functions and Expressions

Functions are defined by equations and applied by juxtaposition, with no parentheses or commas around arguments:

> greet name =
|   "Hello " ++ name ++ "!"

> greet "Alice"
"Hello Alice!"

> madlib animal adjective =
|   "The ostentatious " ++ animal ++ " wears " ++ adjective ++ " shorts."

> madlib "cat" "ergonomic"
"The ostentatious cat wears ergonomic shorts."

if is an expression, not a statement, so every branch must produce a value:

> greet name =
|   if name == "Abraham Lincoln" then
|     "Greetings Mr. President!"
|   else
|     "Hey!"

Lists, Tuples, and Records

  • Lists must be homogeneous (every element the same type) and are manipulated through the List module (List.map, List.sort, List.reverse, …)
  • Tuples hold two or three values of any types; a common use is returning more than one value from a function, e.g. (True, "name accepted!")
  • Records hold many named values: { first = "John", last = "Hobson", age = 81 }, accessed with john.last or the field-access function .last john

Record update creates a whole new record rather than mutating the old one:

> john = { first = "John", last = "Hobson", age = 81 }

> { john | last = "Adams" }
{ age = 81, first = "John", last = "Adams" }

> celebrateBirthday person =
|   { person | age = person.age + 1 }

Read { john | last = "Adams" } out loud as "a new version of John where his last name is Adams." Elm makes the copying efficient through structural sharing: if you update one of ten fields, the new record shares the nine unchanged values.

Notes

The record-update idiom is immutability made ergonomic, the same persistent-data-structure idea that shows up in Clojure and in functional cores generally. Nothing is ever overwritten, which is a big part of why "no runtime errors in practice" is a believable claim.
