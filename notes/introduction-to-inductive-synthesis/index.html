Introduction to Inductive Synthesis

The goal of inductive synthesis is to generate a function that matches a given set of input/output examples. The literature distinguishes two modes. Programming by example (PBE) infers a function given only inputs and outputs, like factorial(6) = 720. Programming by demonstration (PBD) has the user also provide a trace of how the output was computed: factorial(6) = 6 * (5 * (4 * (3 * (2 * 1)))) = 720. Full traces make it easier to infer the intended computation. They are something like context.

The Two Challenges

  • How do you find a program that matches the observations?
  • How do you know the program you found is the one you were actually looking for?

These are fundamentally under-specified problems. There is potentially a large space of programs matching the given observations. Traditional ML focused historically on the second challenge; modern PBE focuses on the space of programs itself. Early systems restricted the space to an extreme degree (literally a short list of programs to scan), but recent synthesis brought powerful mechanisms to search arbitrary program spaces, so the space can be designed to exclude undesirable solutions and focus the search on "reasonable" programs. Ranking is still needed, but if you can search a large, highly constrained space efficiently, you are more likely to get what you were looking for, without the brittleness of the list-of-programs approach.

Programs, Languages, and DSLs

A program, in this context, is a description of how to perform a computation; describing one requires a notation, a programming language, that composes individual syntactic elements with well-defined meaning. Even when the end goal is Python or C, it is often useful to frame the synthesis problem in a narrower notation capturing only the programs relevant to the task: a domain-specific language, conveniently thought of as a subset of a general language with a limited set of constructs and functions.

Functional languages are a good synthesis target: pure functions mean the same inputs always produce the same outputs, simplifying reasoning, and the conciseness means non-trivial programs require discovering only small amounts of code. Compare list reversal in Java and Haskell:

class ListReverser{
    static List reverseList(List myList) {
        List output = new ArrayList();
        for (int i = 0; i < myList.size(); i++) {
            output.add(myList.get(myList.size() - 1 - i));
        }
    return output;
    }
}
reverse lst = case lst of
                [] -> []
                head:rest -> (reverse rest) ++ [head]

Notes

String representations of programs used to be frowned upon for synthesis: sparse (most strings are not valid programs) and wasteful (parse immediately into a structure anyway). Today strings and structured representations are likely to coexist in systems combining symbolic and neural techniques, which is exactly the LLM-era compromise.
