Category Theory: The Essence of Composition

A category is almost nothing: a collection of objects and arrows (morphisms) between them, where arrows compose. If there is an arrow from A to B and one from B to C, then there must be an arrow from A to C — their composition. Morphisms are essentially functions, and composition is the whole game.

Objects, Arrows, and Composition

If f takes an A and returns a B, and g takes a B and returns a C, you can compose them by feeding the result of f into g, producing a function that takes an A and returns a C. This composite is written g ∘ f, read "g after f," and it runs right-to-left:

// C++: g after f, right-to-left
C g_after_f(A a)
{
    return g(f(a));
}
-- Haskell
f :: A -> B
g :: B -> C
g . f   -- composition

The arrow notation is the right mental model rather than thinking of f as returning a value into g. The composite does not depend on f as such; it depends on some value of type B, and f happens to produce one. The objects match end-to-end, and that is all composition needs.

Associativity and Identity

Composition obeys two laws. First, it is associative: given three composable arrows f : A → B, g : B → C, and h : C → D, the grouping does not matter, so parentheses are unnecessary —

h ∘ (g ∘ f) = (h ∘ g) ∘ f = h ∘ g ∘ f

Second, every object A has an identity arrow id_A that loops from A back to itself and acts as a unit of composition: composing it with any arrow into or out of A gives that arrow back.

f ∘ id_A = f and id_B ∘ f = f

The identity is not about a function, it is the function — the "do nothing" arrow for an object, the categorical analogue of multiplying by 1 or adding 0. For f : String → Int, the arrow id_String returns its string unchanged: no effect on the input side, no effect on the output side. The point is that these identity arrows are required to exist for every object, which is why id lives in the standard library:

-- Haskell
id :: a -> a
id x = x

When a Directed Graph Becomes a Category

A directed graph is a set of vertices joined by directed edges (ordered pairs). It becomes a category once you add an identity arrow on every node and a composite arrow for every path. There is no requirement of rich connectivity — this answers a question I had while reading, namely whether every pair of objects must be related. They need not be; a category only insists that the arrows which do exist compose and that identities are present. This construction is the free category on a graph.

Decomposition and the Surface-to-Volume Ratio

Programming is composition turned into a method. Even assembly instructions express something more meaningful than shuffling memory, and we solve large problems by decomposing them into smaller ones until each piece is tractable — a process that only makes sense because we can compose the pieces back together. This hierarchical decomposition is forced on us less by the machine than by our own minds, which can only hold a few chunks at once.

A chunk has two sizes. Its surface is the interface — the type signatures, inputs, and outputs visible from outside, what you must know to use it. Its volume is the implementation — the internal logic and state you do not have to think about. As chunks grow, surface scales like n² while volume scales like n³, so the ratio drops:

size   | surface | volume | ratio
-------|---------|--------|------
small  | 6       | 1      | 6:1
medium | 24      | 8      | 3:1
large  | 54      | 27     | 2:1

A tiny function can have a signature nearly as complex as its body, whereas a well-designed module hides enormous internal complexity behind a small, clean interface. Elegant code finds the cuts where the interface between pieces is thinnest, producing chunks just the right size and number for our mental digestion to assimilate.

Notes

Category theory is "black box" thinking taken to an extreme: it actively discourages looking inside the objects. For f : String → Int you do not care how the length is computed, only that an arrow from String to Int exists. This is what makes the abstraction powerful — two completely different systems can share the same categorical structure. The same lens reframes everyday objects: the web becomes a category with pages as objects and links as arrows, and a social graph becomes one with people as objects and friendships as morphisms. Once composition and identity are in place, functors are the next step — the structure-preserving maps between categories.
