Program Synthesis: Introduction and Definitions

Program synthesis is the class of techniques that generate a program from a collection of artifacts establishing semantic and syntactic requirements for the generated code. Code presents unique opportunities here: unlike other tasks where LLMs have shown promise, code benefits from precise semantics, which let us test it and reason formally about its behavior. Automating software development has been a dream since 1945, with Alan Turing arguing for the Automatic Computing Engine.

Synthesis vs. Its Neighbors

  • Compilation shares the same goal of generating software from a high-level description of its behavior, but we expect synthesizers to discover how to perform the desired task. Search used to be the distinguishing factor, though the line has blurred: compilers now use search to optimize generated code, and LLMs synthesize entire programs without explicit search.
  • Logic programming dreamed of programmers expressing requirements in logical form, with the runtime deriving satisfying outputs through search and deduction. Two distinctions: it relies on a generic algorithm to search for a solution to every problem rather than discovering an algorithm for the problem at hand (often making it slow), and an under-specified problem can yield a solution the user did not expect.
  • Machine learning seeks a predictor matching a dataset of input/output pairs; squint and it is synthesis of a function mapping each x to its y. But ML restricts the function space to a fixed structure (linear, neural network, …) while synthesis discovers what structure is needed, such as loops, branches, or recursion. Synthesis also traditionally demands programs that always precisely match the specification, where ML embraced noisy data and real-valued success measures from the start. That gap is narrowing from both sides.

Specifying Intent

FlashFill in Excel/Sheets is the canonical deployed example: give a few examples of how the remaining cells should look and the synthesized program fills them in. It popularized input/output examples as a specification form. The standing challenge is how users should communicate goals at all: natural language is becoming the preferred specification, but it is imprecise.

Notes

The compiler/synthesizer/ML triangle is really one axis: how much of the how the human provides versus the machine discovers. That framing makes "LLMs as synthesizers" feel less like a rupture and more like the search component getting a vastly better prior.
