List and Text CRDTs

Ordered collections are where the unique set needs a twist. In a list or a text document users insert and delete elements at positions, and inserting or deleting a character shifts the indices of everything after it — the behavior of JavaScript's Array.splice. Referring to those positions by raw index is exactly the index-instability problem again, so a list CRDT gives every element its own immutable list CRDT position at the moment it is typed.

Unlike a generic UID, these positions are ordered: given two positions p and q you can always ask whether p < q or q < p. A text CRDT is the same construction specialized to individual characters as values, which makes the state trivial to describe:

  • Sort all (position, char) elements by position
  • Display the characters in that order

What the Ordering Must Guarantee

For that sort to give every replica a "stable, consistent" sequence, the positions have to satisfy three properties:

  • Total order — every position has a definite less-than relationship with every other position, even ones created concurrently by different users. There are no ties: "we both inserted at position 5, now what?" still resolves to a single agreed order
  • Immutability — once p comes before q, that never changes no matter what is inserted or deleted around them. A text editor does not reshuffle chapters because someone edited nearby, and the relationship holds even if the element between them is later deleted
  • Transitivity — ordinary ordering logic: if A < B and B < C, then A < C

Positions with all three properties are genuinely hard to implement correctly — the survey spends its closing paragraphs on the machinery — but the payoff of the abstraction is that you do not have to understand the internals. You insert and delete against opaque positions and trust that the order they induce is total, stable, and transitive.

Notes

The split is the satisfying part: identity (UIDs) handles which element an operation refers to, and order (list positions) handles where it sits, and neither one leaks index arithmetic into the operations themselves.

Source: Matt Weidner's CRDT survey, part 2.
