Dafny: Logic

The most basic level of logic is propositional, the study of statements, sentences that are either true or false. Dafny makes these executable claims: a method with an empty body does nothing at runtime, we are just asking the verifier to evaluate a logical expression.

Connectives

  • A conjunction holds when both sides are true: ensures 1 + 2 == 3 && 1 * 2 == 2
  • A disjunction holds when at least one side is true: ensures 1 + 2 == 3 || 1 * 2 == 2
  • A negation is the opposite of a statement; the negation of "i like soda" is "i don't like soda": ensures ! (1 * 2 == 3)
  • An implication "if a then b" holds whenever a being true forces b to be true

An implication P ⇒ Q is only false when P is true and Q is false; in every other case, including when P is false, the whole implication is true:

P (left) | Q (right) | P ==> Q
---------|-----------|--------
true     | true      | true
true     | false     | false
false    | true      | true
false    | false     | true

When Dafny Says a Postcondition Might Not Hold

I first read this error as Dafny saying false, but it really means "I cannot prove this ensures clause is always satisfied." Either the postcondition is actually violated for some input, or it is true but Dafny lacks sufficient hints (invariants, lemmas) to prove it, leaving it unproven rather than false. An invariant is a property that must hold at specific points in the program, which the verifier can use as a checkpoint.

Quantifiers

  • The universal quantifier says the predicate is true for all possible inputs
  • The existential quantifier says the predicate has at least one true input
  • Negation swaps them: a negated universal becomes an existential, and vice versa
method InterestingFact()
    ensures forall x :: x + 1 == 2 <==> x == 1
{}

This proves a fact about arithmetic, not a specific calculation: forall covers every possible x, and <==> requires both directions, so together they prove 1 is the unique solution to x + 1 = 2.
