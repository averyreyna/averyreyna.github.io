Registers: Last Writer Wins and Multi-Value

Not every conflict has a structural answer the way list order does. When several users set the same single value concurrently and there is no better way to reconcile them, a register has to make a choice, and the two standard choices — discard all but one, or keep them all — are themselves CRDTs.

Last Writer Wins

Last writer wins (LWW) resolves the conflict by picking the "last" value as the winner: the operation with the greatest assigned timestamp. Given a history of set operations, the current state is simply the value carried by the latest timestamp. The minimal case is the LWW register, a CRDT for a single variable whose sole operation is set(value, timestamp).

The timestamp is usually a Lamport timestamp, which keeps the choice compatible with the causal order, though clock skew can still produce surprising winners, so it is worth paying attention to the granularity of writes. Applying the same rule per entry gives an LWW map, with operations set(key, value, timestamp) and delete(key, timestamp).

Multi-Value Register

Sometimes discarding the losers is the wrong call, because LWW destroys someone's work. A multi-value register keeps every conflicting value instead. Its single operation is set(x), and its current state is the set of values whose operations are at the heads of the operation history — the maximal operations in the causal order, the ones nothing comes after.

                set("green")   set("green")   set("grey")
                   o--------------o--------------o
                  /
  set("purple") -o
                                    set("blue") -o   <- heads: nothing
                                                       follows these two

LWW would keep only "grey", the last edit along the graph, and throw "blue" away. The multi-value register instead reports both unresolved heads, so the state here is {"grey", "blue"} and the concurrent edit survives for the app to surface. Applied per entry this is a multi-value map, with operations set(key, value) and delete(key).

Notes

Registers are the first place the design question stops being "how do we converge" and becomes "what do users want" — LWW and multi-value converge equally well, and the choice between losing an edit and exposing a conflict is a semantic one, not a correctness one.

Source: Matt Weidner's CRDT survey, part 2.
