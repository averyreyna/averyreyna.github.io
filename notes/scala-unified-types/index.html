Scala: Unified Types

In Scala, all values have a type (numbers, functions, everything), and the whole hierarchy hangs off a single top type. The diagram below shows a subset of it:

[Image: Diagram of the Scala type hierarchy rooted at Any]

Top of the Hierarchy

  • Any is the supertype of all types (the top type); it defines universal methods like equals, hashCode, and toString, and has two direct subclasses
  • AnyVal represents value types, with nine predefined and non-nullable: Double, Float, Long, Int, Short, Byte, Char, Unit, Boolean; Unit carries no information and has exactly one instance, ()
  • AnyRef represents reference types; every user-defined type is a subtype, and on the JVM it corresponds to java.lang.Object

Because everything is an Any, a heterogeneous list is perfectly typeable:

val list: List[Any] = List(
  "a string",
  732,  // an integer
  'c',  // a character
  true, // a boolean value
  () => "an anonymous function returning a string"
)

list.foreach(element => println(element))

Casting

Value types can be cast in one direction only:

[Image: Diagram of permitted value-type casts, e.g. Byte to Short to Int]

val x: Long = 987654321
val y: Float = x.toFloat  // 9.8765434E8 (some precision is lost)
val z: Long = y           // Does not conform; casting is unidirectional

val face: Char = '☺'
val number: Int = face    // 9786

Long-to-Float conversion is deprecated in newer Scala versions precisely because of that potential precision loss.

Bottom of the Hierarchy

  • Nothing is a subtype of all types (the bottom type); no value has type Nothing, and it signals non-termination: a thrown exception, program exit, or an infinite loop
  • Null is a subtype of all reference types, exists mostly for interoperability with other JVM languages, and should almost never be used in Scala code

Notes

Top and bottom types make the hierarchy a lattice rather than a tree, which is what lets the type checker compute least upper bounds for things like the branches of an if. The same top/bottom structure reappears abstractly in lattice theory.
