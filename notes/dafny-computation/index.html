Dafny: Computation

Algorithms represent a sequence of steps in some process; at the lowest level, a procedure represents operations upon symbols in a formal system. Computation is itself a type of formal system, the symbols being 0s and 1s, the inference rules representing procedures.

Assertions

method Main() {
    var v := 3;
    assert 0 <= v;
}

The assertion claims the value of v will be non-negative, and Dafny confirms it. Assert something false and Dafny returns an assertion violation. Assertions work on computed results too: storing 1 + 2 and asserting the result is larger than 0 verifies fine.

Functions vs. Methods

  • Functions contain a single expression, can be used in specifications, cannot be used in method bodies, and are not part of the final program, acting as substitution at compile time
  • Methods can contain multiple statements, cannot be used in specifications, can be called from method bodies, and are part of the final program, computation at runtime

In Dafny, functions are ghost by default. They exist only for the verifier, not in the compiled executable. The "substitution at compile time" phrasing describes how the verifier handles function calls: it can unfold the function body wherever the function is called in a proof context, rather than treating it as an opaque call with pre/postconditions (which is how methods work).

Here is the same product computation in both forms. Note how the function can call itself in its own ensures clause, while the method specifies an output variable that holds the return value:

function Product(a: int, b: int): int
    ensures Product(a, b) == a * b
{
    a * b
}

method Product(x : int, y : int) returns (product : int)
    ensures product == x * y;
{
    product := x * y;
}

Verification and compilation are independent steps. You can compile without verifying, the whole point of Dafny being that you don't want to. The split in what runs: ghost code (erased at compile time; requires/ensures/invariant) versus non-ghost code (method bodies, regular variables, imperative logic). The compiled executable can target any of several languages. Also: print is a statement, not a function call.

Predicates

predicate GreaterThanZero(n : nat)
{
    n > 0
}

method Main(x : int) returns (y : int)
    ensures GreaterThanZero(x)
{
    y := x * 2;
}

Predicates are top-level declarations, boolean functions usable in specifications, but not definable inside one.

Recursion and Termination

function Summation(n : nat): nat
    decreases n
{
    if n == 0 then 0 else n + Summation(n-1)
}

For tail-recursive functions the computation is captured completely by the arguments: some variable carries all the work done so far. Summation is not tail recursive: n does not keep track of the result until the base case is hit, so the additions pile up on the way back out.

A method can then be verified against the function as its specification:

function Summation(x : nat): nat
    decreases x
{
    if x == 0 then 0 else x + Summation(x-1)
}

method Sum(x : nat) returns (summation : nat)
    ensures summation == Summation(x)
{
    summation := Summation(x)
}

Algebraic Datatypes

datatype Tree<T> = Leaf | Node(nat, TreeNat, TreeNat) is not initializing a tree; it declares the shape of what a tree can be:

  • datatype defines an algebraic datatype (superficially like a Python @dataclass, but more powerful: it describes every possible form the data can take)
  • Tree<T> is the type name with a generic parameter
  • Leaf | Node(...) are the two possible forms, separated by |
  • Node(nat, TreeNat, TreeNat) holds three things: a nat and two subtrees
