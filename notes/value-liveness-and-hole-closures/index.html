Value Liveness and Hole Closures

Inferring a hole's type from live data gives every editor state a type. The dynamic counterpart gives every state a value: a hole-tolerant evaluator that runs the partial pipeline over the actual rows. The distinction is worth holding onto. Type liveness is a moving squiggle, while value liveness is moving numbers, and the moving numbers are closer to what people usually mean by "live."

Two Mirrored Walks

The type checker and the evaluator are the same tree walk over the same program, carrying different things. The static walk carries an expected type and a context and produces a type at each node. The dynamic walk carries the live data in scope and produces a value at each node. At a hole the static walk stops synthesizing, while the dynamic walk returns a closure and keeps going. Both are tolerant: where the static side falls back to an internal unknown, the dynamic side falls back to an indeterminate value, so neither one crashes on an incomplete program.

Hole Closures over Live Data

The central move on the dynamic side is that each hole captures the data in scope as a closure: here is the live table at this point, and a value will eventually go here. This is the same idea as a lambda closure capturing its environment, except the environment is not a set of lexical bindings but the live table itself. Aggregations are written to tolerate holes, so the result shows gaps where the holes are and a gap turns into a real number the moment you name the column, with no separate run step.

The Beats This Buys

Two small demonstrations follow from this. The first is a data swap: change the source file and the numbers in the result move on their own, which is more convincing than a squiggle that moves. The second is a type error shown next to its consequence. A non-numeric column in a sum draws its squiggle, and at the same time the result shows the actual garbage it would produce, side by side, before anything runs.

Notes

Together with typed holes and gradual consistency and schema inferred from live data, this completes the arc: static and dynamic meaning for every editor state, the idea being carried over from Hazel into plain text. The closure here is close kin to the one in the lambda calculus; what changes is what gets captured.
