Elm: Types and Error Messages

Every Elm expression has a type, and the compiler checks all of them before anything runs. The error messages are the best part. They read like a helpful colleague rather than a stack trace:

-- TYPE MISMATCH ---------------------------------------------------------------

The argument to function `toFullName` is causing a mismatch.

6|   toFullName { fistName = "Hermann", lastName = "Hesse" }

Function `toFullName` is expecting the argument to be:

    { …, firstName : … }

But it is:

    { …, fistName : … }

Hint: I compared the record fields and found some potential typos.

    firstName <-> fistName

Reading Type Signatures

  • Asking the REPL for a function's type prints its signature: String.length : String -> Int
  • round : Float -> Int means round must take a Float argument and will definitely return an Int; "definitely" is the operative word, since the compiler enforces it

Notes

The typo-detection hint above is a small thing, but it shows the design philosophy: the type checker has all the information needed to guess what you meant, so it should. Compare with the wall of text a similar mistake produces in most ML-family compilers.
