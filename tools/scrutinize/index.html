Avery Reyna

Scrutinize

May 11, 2026

Scrutinize is an ephemeral writing assistant. You give it a topic, it generates an essay via the DeepSeek API, and then you annotate it. Nothing persists — the essay and every mark you make exist only in your browser session. Close the tab and it's gone.

The annotation system is the core of it. A collapsible toolbar on the right side of the screen exposes twenty codes grouped into five categories: Structure & Flow (LEDE, FLOW, SPFIC, WALL), Clarity & Precision (CLEAR, AMBIG, TERM, DIR), Style & Tone (TONE, BRAND, COLOR, FRESH), Inclusion & Impact (INCL, EMPATH, WIIFM, A11Y), and Accuracy & Evidence (FACT, EXMPL, QUOTE, HYPER). You select a code, then drag over any span of text to attach it. The selection gets a translucent highlight in the group's color; hovering it opens a popup card that shows the code, its description, and lets you attach a freeform note.

Overlapping annotations are blocked at the selection handler level. When you attempt to mark a range that intersects an existing one, the selection is cleared and the toolbar resets — no merge logic, no resolution UI. The document renders annotations by sorting them by start position and slicing the raw content string into alternating plain and highlighted nodes, so the display is purely derived from state and rerenders cleanly when anything changes.

A suggestions panel fixed to the left column lets you collect revision ideas separately from the inline annotations. Each suggestion is a text entry with an optional evidence field and an optional link to one of the existing annotation IDs. The panel is hidden below a viewport threshold where the layout would collapse, since the three-column structure — suggestions panel, document, annotation toolbar — needs enough horizontal room to be readable.

The DeepSeek call itself is a single chat/completions request with a system prompt instructing the model to write a structured essay in plain text, no markdown. The API key is injected at build time via an environment variable; there's no backend. Essay generation happens once per topic submission — editing the topic and resubmitting replaces the document entirely, discarding all annotations with it.
